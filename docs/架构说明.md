# 机械臂算法架构

## 数据流

```text
RGB-D observation
  -> lzt_perception: Top-K T_camera_object + confidence/covariance
  -> lzt_grasp_planning: T_object_grasp + robust grasp ranking
  -> lzt_kinematics: target tool pose -> joint solution
  -> lzt_motion_planning: joint states -> collision-free geometric path
  -> lzt_trajectory: path -> q(t), dq(t), ddq(t)
  -> lzt_control: trajectory -> joint/Cartesian/gripper/force commands
  -> lzt_mujoco or a future real-robot adapter
```

物体位姿、抓取位姿、几何路径、时间轨迹和控制命令是五种不同的数据，不允许由一个
“执行脚本”隐式混为一体。

## 包边界

- `lzt_common`：只保存跨算法共用的数据契约、SE(3)、标定、物料配置和资源解析。
- `lzt_interfaces`：ROS 进程间接口，当前定义物体位姿假设、抓取候选、关节路径、
  路径规划服务和轨迹执行 action。
- `lzt_description`：UR5e、Tracer、Robotiq 2F-85、相机、场景、CAD 配置和标定资源。
- `lzt_perception`：掩膜评价/修正、Top-K 位姿、几何门控、RGB-D 精修和可靠性估计。
- `lzt_grasp_planning`：CAD 平行夹爪候选和多假设风险感知取放排序。
- `lzt_kinematics`：后端无关的 IK 接口与结果；不包含碰撞或控制。
- `lzt_motion_planning`：无时间戳的关节路径和碰撞接口；不输出执行命令。
- `lzt_trajectory`：路径插值和时间参数化；不访问相机、CAD 或仿真世界。
- `lzt_control`：轨迹控制器、机器人状态和力控接口；不选择抓取目标。
- `lzt_mujoco`：工作站装配、MuJoCo Jacobian IK、逐路径接触检查和执行后端。
- `lzt_bringup`：ROS 节点、参数与 launch，只负责组合，不保存算法实现。
- `lzt_benchmark`：BOP/ROBI 转换、覆盖率和论文指标。
- `lzt_system_tests`：包边界、算法回归和后续端到端测试。
- `lzt_examples`：最小使用示例。
- `lzt_cad_grasp_ros`：旧可执行程序兼容入口，不能新增算法。

## 当前完成度

| 层 | 当前状态 | 尚未完成 |
|---|---|---|
| Perception | 原有 Top-K、门控、精修和可靠性代码已迁移并通过回归 | 在线分割前端和全数据统计提升仍需实验 |
| Grasp planning | CAD 候选和 CVaR/多假设排序已迁移 | 更多工业物料和真实抓取对照 |
| Kinematics | 已定义通用接口；MuJoCo DLS Jacobian IK 可用 | 独立解析 FK/Jacobian、MoveIt/实机实现 |
| Motion planning | 已定义 JointPath/CollisionChecker；MuJoCo 路径碰撞审计可用 | RRT/OMPL 等真正的绕障路径搜索 |
| Trajectory | 已提供确定性线性时间参数化 baseline | 速度/加速度约束、梯形/S 曲线和平滑优化 |
| Control | 已定义轨迹、机器人状态和力控接口 | 闭环轨迹跟踪、笛卡尔控制、阻抗/导纳控制 |
| Backend | MuJoCo 场景、IK 和碰撞链路可用 | 真实 UR5e/夹爪/力传感器适配 |

因此，本次重构证明了包边界和现有算法兼容性，但不等于已经完成运动规划、闭环控制或
力控算法。后续新增实现必须放入对应层，并由 `lzt_system_tests` 验证依赖方向。
